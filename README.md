# Mars Ops / ГОРИЗОНТ — хакатон Space Apps 2026

Экосистема для выходов астронавтов на поверхность Марса (кратеры Jezero и Gale). Это три веб-приложения на одной
кодовой базе, связанные через Supabase, плюс офлайн-пайплайн данных и алгоритмов по открытым данным NASA.

| Приложение | Адрес | Что делает |
|---|---|---|
| **Mission Control** (диспетчер) | `/dispatch` | глобус Марса с экипажами и аномалиями; экипажи, планы выходов, аномалии, прогнозы, сообщения |
| **Ship Console** (корабль) | `/ship/:crewId` | карта зоны экипажа; безопасный маршрут (A*), проверка окна выхода, отправка маршрута в шлем, старт и конец выхода, обход новой опасности |
| **EVA Helmet** (VR-шлем) | `/helmet/:crewId` | Meta Quest (WebXR): маршрут под ногами, HUD, мини-карта, голосовые предупреждения, телеметрия |

## Структура репозитория

```
frontend/     веб-приложения: Vite + React 19 + TypeScript + three.js / react-three-fiber + Supabase
  src/          код (pages, dispatch, astro — 3D-сцена шлема, eva, components, lib)
  public/       карты высот зон, текстуры, данные, озвучка
  supabase/     SQL-схема базы
  scripts/      одноразовые сборщики данных для фронта (уже запущены, результат в public/)
  docs/         состояние проекта, источники, VR: интеграция и чек-лист проверки
  AGENTS.md     правила для ИИ-агентов, работающих с фронтом
backend/      данные и алгоритмы на Python (рельеф, цели, маршруты, слои, локализация по горизонту)
  export/       готовые файлы для фронта
  out/          отчёт, картинки проверки, слайды, результаты «где я»
  scripts/      шаги пайплайна p0…p6
  src/gor/      библиотека: чтение данных, слои, маршрутизация, силуэты горизонта
  viewer/       простой 3D-просмотрщик данных бэка
vercel.json   деплой фронта из frontend/
```

## Быстрый старт — фронт

```bash
cd frontend
cp .env.example .env.local   # VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY из Supabase → Project Settings → API Keys
npm install
npm run dev                  # http://localhost:5173
```

- **Новая база Supabase:** SQL Editor → вставить `frontend/supabase/schema.sql` → Run.
- **Сборка:** `npm run build` (сначала проверяет типы, потом собирает), проверка типов отдельно — `npm run typecheck`, линтер — `npm run lint`.
- **VR на Quest:** открыть задеплоенный сайт (HTTPS) в браузере Quest → EVA Helmet → **Enter VR**.
  Dev-сервер для шлема: `npm run dev:quest` (или `dev:vr`) — HTTPS в локальной сети с самоподписанным сертификатом.
  Параметры адреса: `?speed=30` — во сколько раз быстрее реальной ходьбы идёт симуляция, `?lite` — облегчённая графика.
- Подробно — [`frontend/README.md`](frontend/README.md), состояние VR — [`frontend/docs/STATE.md`](frontend/docs/STATE.md),
  проверка на шлеме — [`frontend/docs/VR_TEST.md`](frontend/docs/VR_TEST.md).

## Деплой (Vercel)

Корневой `vercel.json` ставит зависимости и собирает фронт в `frontend/`, результат берётся из `frontend/dist`. Правила
`rewrites` для одностраничного приложения сохранены, в настройках Vercel менять ничего не нужно.
Если в проекте Vercel выставить Root Directory = `frontend`, корневой `vercel.json` перестанет действовать: тогда блок
`rewrites` нужно перенести в `frontend/vercel.json`.

## Бэк — данные и алгоритмы (`backend/`)

Офлайн-пайплайн на Python. Сервер не нужен, результат — статические файлы в `backend/export/`.

| Файл | Что внутри |
|---|---|
| `export/terrain/` | рельеф 4×4 км (HiRISE 1 м → узлы через 3.9 м, 1025² и 513²) + фон 40×40 км (CTX 20 м), текстуры 4096/2048, `meta.json`, пример загрузки в three.js |
| `export/targets.json` | база (лендер Perseverance) + 7 мест, где Perseverance брал образцы; координаты — по путевым точкам ровера NASA |
| `export/routes.json` | 4 миссии: путь с накопленными временем, O₂ и дозой; точка невозврата; выброшенные цели с причиной; пути к укрытию при вспышке |
| `export/layers/` | слои карты: опасность (уклон, неровности), доза радиации, зоны возврата |

**Система координат бэка:** метры от центра участка (77.4259879° в.д., 18.4437836° с.ш.), `x` — восток, `y` — север,
`h` — высота от `h_ref`. В three.js — `position = (x, h, -y)`. Подробно — [`backend/export/README.md`](backend/export/README.md).

### Как считается маршрут
Карта высот делится на клетки 5×5 м (800×800). В каждой клетке считаются уклон (круче 15° — запрет), неровности,
скорость ходьбы (формула Тоблера × 0.6 на скафандр), расход O₂ и доза радиации по доле открытого неба.
Цена клетки — секунды на метр с надбавками. Путь ищется алгоритмом минимальной стоимости (Дейкстра,
`skimage.graph.MCP_Geometric`), порядок целей — перебором. Потом проверяются лимит 4 ч, запас O₂ с резервом 20%
и возврат на базу; если миссия не влезает, выкидывается цель с худшим приоритетом.

| Миссия | Цели | Дистанция | Время | O₂ |
|---|---|---|---|---|
| m1 Artuby Ridge | 1 | 2.0 км | 69 мин | 77 л |
| m2 Séítah | 2 | 1.9 км | 93 мин | 103 л |
| m3 Séítah + дельта | 2 из 4 (2 выброшены: не влезли в 4 ч) | 6.4 км | 201 мин | 228 л |
| m4 фронт дельты | 3 | 6.4 км | 226 мин из 240 | 254 л, есть точка невозврата |

### «Где я» — локализация по линии горизонта (без GPS)
Заранее по карте высот считается справочник: как выглядит горизонт (угол над уровнем глаз в 360 направлениях) из
каждой точки участка. На месте камера даёт линию «небо/грунт», а уровень берётся с акселерометра. Ищется точка, где
посчитанный горизонт совпадает с увиденным, и попутно определяется направление взгляда.

Проверено на **10 настоящих панорамах Perseverance** (Navcam, архив NASA PDS; где стоял ровер, известно от NASA):

| Режим | Медиана ошибки | Точнее 100 м |
|---|---|---|
| 1 панорама 360° | 313 м | 40% |
| 2 остановки подряд + подсчёт шагов (±5%) | 34 м | 68% |
| **3 остановки подряд + подсчёт шагов** | **27 м** | **82%** |

- Посчитанный по карте горизонт совпадает с реальным с точностью 0.1–0.5° (на 8 из 10 стоянок).
- Кадр шириной 90° не работает (~1 км): на ровном дне кратера много «двойников», поэтому надо оглядеться на 360°.
- Выборка маленькая (10 стоянок), настройки выбирались на ней же. Шагомер смоделирован, камера — роверная, не шлемная.
- Бонус: тот же силуэт даёт долю открытого неба → доза радиации и выбор укрытий.

## Как фронт и бэк связаны сейчас

**Пока никак.** Фронт строит маршруты своим A* по своим картам высот 20 м (`frontend/public/zones/`,
`frontend/src/lib/`) и хранит их в `work_plans.route`. Данные бэка лежат в `backend/export/` как готовые файлы
и к фронту не подключены. Чтобы подключить:
- рельеф — `export/terrain/*.u16` + `meta.json` (пример: `export/terrain/loader_example.js`);
- маршруты и цели — `export/routes.json`, `export/targets.json`; в точках есть `lon`/`lat` для карт Leaflet;
- система координат и масштабы у фронта и бэка разные (зоны фронта — 20 м/px, участок бэка — 4×4 км с точностью 1 м).

## Источники данных

- **HiRISE** (камера орбитального аппарата Mars Reconnaissance Orbiter): карта высот 1 м и ортоснимок 25 см, Jezero.
  Мозаики USGS для посадки Mars 2020 (Terrain Relative Navigation).
- **CTX** (тот же аппарат): карта высот 20 м и ортоснимок 5 м на весь кратер Jezero (JPL).
- **MOLA** (Mars Global Surveyor): глобальная карта высот 463 м, только западный край дальнего фона.
- **Perseverance**: путевые точки траверса (NASA/JPL MMGIS), список образцов (science.nasa.gov),
  панорамы Navcam (NASA PDS Imaging Node).
- **Радиация:** Curiosity RAD, Hassler et al. 2014 (0.64 мЗв/сут на поверхности).
- Источники данных фронта — [`frontend/docs/SOURCES.md`](frontend/docs/SOURCES.md).

## Ограничения (честно)

- Маршруты, O₂, доза и показатели скафандра — модели и демонстрация, а не реальная телеметрия и не сертификация безопасности.
- Формула ходьбы земная, гравитация Марса не учтена; камни меньше ~1–3 м карта высот не видит.
- Локализация по горизонту проверена на панорамах ровера, а не на камере шлема.
- VR на физическом Quest: см. [`frontend/docs/STATE.md`](frontend/docs/STATE.md) — часть проверок там помечена **NOT TESTED ON DEVICE**.
- Supabase в демо — облачный сервис. На реальном Марсе база должна стоять локально (база или корабль), а Земля
  получает копию с задержкой 4–24 мин. Маршруты и «где я» работают автономно и связи не требуют.
