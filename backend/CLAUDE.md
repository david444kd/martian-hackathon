# ГОРИЗОНТ — пакет данных и алгоритмов (Space Apps 2026, Martian Map)

Инструкция для Claude Code. Прочитай целиком перед началом.

## 0. Контекст

Команда делает экосистему из трёх веб-экранов, связанных через Supabase:
1. **Диспетчер** — планирует миссии, ставит маршруты, запускает события (солнечная вспышка).
2. **Корабль** — карта Марса и миссий, только просмотр.
3. **VR-шлем (WebXR, Meta Quest)** — вид астронавта: путь под ногами, мини-карта, HUD.

Бэкенда нет: статический фронт (three.js) на Vercel/Cloudflare + Supabase.
Место — кратер **Jezero**, район посадки Perseverance.

**Твоя задача (этот репозиторий)** — подготовить для фронта НАСТОЯЩИЕ данные и результаты
алгоритмов в виде статических файлов в папке `export/`, плюс демо локализации по горизонту
и схемы для слайдов. Фронт уже работает на моках — наши файлы должны подменять моки
без переделки фронта.

Если у фронта уже есть формат мока — сначала спроси/найди его и подстройся под него.
Форматы ниже — предложение по умолчанию.

## 2. Правила

- **Честность.** Ничего не подгонять. Все допущения — в `ASSUMPTIONS.md`. Если что-то не
  сработало — так и написать в `out/REPORT.md`.
- **Проверка картинкой на каждом шаге** (`out/check/*.png`): рельеф, текстура, совпадение
  рельефа и текстуры, маршрут поверх запретов, слои.
- **Не качать гигабайты зря.** Сначала читать окно через GDAL `/vsicurl/<url>` в rasterio.
  Полное скачивание — только если окно не читается. Кэш в `data/raw/`, повторно не качать.
- **Размер файлов для веба:** каждый файл в `export/` ≤ 20 МБ (лимит Cloudflare Pages ~25 МБ
  на файл), текстуры ≤ 4096 px (+ версия 2048 px для Quest).
- Если ссылка не работает — найти актуальную на странице-источнике, не выдумывать.
- Код простой, единицы в именах переменных (`dist_m`, `slope_deg`, `time_s`).
- Перед тяжёлым расчётом оценить время; если > 5 минут — огрубить сетку.

- **Карта высот HiRISE, Jezero, 1 м** (USGS, мозаика Mars 2020 TRN, ~1.8 ГБ):

  Страница: https://astrogeology.usgs.gov/search/map/mars_2020_terrain_relative_navigation_hirise_dtm_mosaic
- **Ортоснимок HiRISE 25 см** (~3.2 ГБ, читать только окно):
  страница https://astrogeology.usgs.gov/search/map/Mars/Mars2020/JEZ_hirise_soc_006_orthoMosaic_25cm_Eqc_latTs0_lon0_first
- **Дальний рельеф (кромка кратера)** — CTX DEM мозаика Mars 2020 (20 м) с
  https://astrogeology.usgs.gov/search/map/mars-2020-jezero-crater-landing-site-products
  (при недоступности — MOLA). Нужен для силуэтов горизонта и для фона в 3D.
- **Места образцов Perseverance** — каталог образцов NASA (Mars Rock Samples) / слои JPL MMGIS
  для Mars 2020. Если координаты не находятся автоматически — оставить в `targets.json`
  5–6 точек с пометкой `"coords_source": "manual"` и сказать человеку выписать их с карты NASA.
- Проекция данных USGS — Eqc, метры. CRS брать из файла, переводы — `pyproj` с этим CRS.

### Участок (AOI)
Ориентир — место посадки Perseverance (Octavia E. Butler, около 18.44° с.ш., 77.45° в.д.;
уточнить по данным) и начало траверса к дельте.
- **Ближний участок:** 4×4 км. Для маршрутов сетка 5 м (800×800). Для 3D — карта высот ~4 м/px.
- **Дальний участок:** ~40×40 км вокруг того же центра, 80–128 м/px — фон и горизонт.

### Система координат для фронта (ВАЖНО)
Все точки в `export/` — в **локальных метрах** от центра ближнего участка:
`x` — на восток, `y` — на север, `h` — высота (м, относительно `h_ref` из `meta.json`),
плюс `lon`, `lat` для справки. В three.js ось вверх — Y, поэтому фронт ставит
`position = (x, h, -y)`. Это написать в `export/README.md`.

## 7. P3 — маршруты `export/routes.json`

### 7.1 Слои (сетка 5 м)
- **Уклон, °** — `numpy.gradient`. Круче **15°** — запрет.
- **Неровности (камни)** — из карты 1 м: вычесть сглаженную (окно ~5 м), в каждой клетке 5 м
  взять максимальный остаток. Выше **0.5 м** — запрет, ниже — штраф. Порог проверить глазами
  на ортоснимке с валунами.
- **Скорость** — Тоблер `v = 6·exp(−3.5·|S + 0.05|)` км/ч, S — тангенс уклона;
  симметрично: `(v(S)+v(−S))/2`; × поправка скафандра **0.6**.
- **Кислород** — мощность `W = 350 Вт × (1 + 0.05 × slope_deg)`; литры O₂ = `W·t / 20 100 Дж/л`.
- **Доза** — базовая мощность на поверхности по Curiosity RAD ≈ 0.67 мЗв/сут (проверить по
  источнику, Hassler et al. 2014) × доля открытого неба из силуэтов (см. 9.1), сетка 50 м → 5 м.
Все числа — допущения, записать в `ASSUMPTIONS.md`.

### 7.2 Цена и поиск
`skimage.graph.MCP_Geometric` умножает цену на длину шага → цена задаётся **на метр**:
```python
sec_per_m = 1.0 / v_mps
cost = sec_per_m * (1 + w_rough * rough_norm + w_dose * dose_norm)
cost[forbidden | nodata] = np.inf
```
Пресеты: `fast` (веса 0) и `safe` (w_rough=1, w_dose=0.5).
- Поиск от каждой точки (база + цели) один раз → попарные пути.
- Порядок целей: перебор всех перестановок (≤3 цели → ≤6 вариантов), база → цели → база.
- Склеить куски в один путь, проредить до точки каждые ~5–10 м.

### 7.3 Оценка и проверки
По пути накопительно: `t_s`, `o2_l`, `dose_msv`, расстояние, максимум уклона, + `stop_min` на целях.
- Лимит выхода 4 ч, резерв кислорода 20% от запаса (запас — допущение, например 8 ч хода).
- Возврат: для каждой точки «потрачено + время до базы ≤ лимит». Время до базы — из одного
  `MCP_Geometric` от базы. Первая точка, где запас < 10%, → `no_return_index`.
- Не проходит — выкинуть цель с худшим приоритетом, записать причину в `dropped`.

### 7.4 Маршрут к укрытию (для события «вспышка»)
Для 3–4 точек вдоль каждого маршрута (25/50/75%): найти ближайшую по времени клетку с минимальной
долей открытого неба (под обрывом/у стенки кратера) и путь туда → `shelters`.

### 7.5 Формат
```json
{"generated": "ISO-время", "source": "USGS HiRISE DTM Jezero 1 m", "preset": "safe",
 "missions": [{
   "id": "m1", "name": "…", "target_ids": ["t1","t3"],
   "path": [{"x":0,"y":0,"h":0,"lon":0,"lat":0,"t_s":0,"o2_l":0,"dose_msv":0}],
   "stops_index": [120, 340],
   "no_return_index": 400,
   "summary": {"distance_m":0,"time_min":0,"o2_l":0,"dose_msv":0,"max_slope_deg":0},
   "dropped": [],
   "shelters": [{"from_index": 200, "path": [{"x":0,"y":0,"h":0}], "time_min": 0,
                 "dose_reduction_pct": 0}]
 }]}
```
Сделать 3–4 миссии разной длины (одна цель рядом, две цели, длинная к дельте).
Проверка: `out/check/p3_<id>.png` — маршрут поверх слоя запретов и ортоснимка.

## 9. P5 — демо горизонта (на синтетике)

### 9.1 Силуэты (`horizon.py`)
Для точки P, высота глаз 1.7 м: по азимутам 0..359° луч с логарифмическим шагом до 40 км
(ближний рельеф 5 м + дальний 80–128 м). Угол: `atan((h − h_P − 1.7 − d²/(2R)) / d)`,
R = 3 389 500 м (кривизна Марса). Силуэт = максимум по лучу → 360 чисел. numba, parallel.
Доля открытого неба = среднее по азимутам `(1 − sin(угол_горизонта))` — идёт в слой дозы.
База силуэтов: сетка **50 м** по ближнему участку (~6400 точек) → `data/proc/horizons.npy`.

### 9.2 Тест локализации (честный)
50 случайных точек. Для каждой:
- «фото» = силуэт, посчитанный по **детальной** карте (1–2 м) в точке со случайным сдвигом
  внутри клетки, + шум, + случайный поворот (компаса нет), + только 90° обзора;
- поиск по базе 50 м: скольжение окна 90° по 360°, нормированная корреляция, максимум;
- результат: найденная точка, ошибка в метрах.
Выход: `out/horizon/stats.md` (медиана и 90-й перцентиль ошибки, доля < 100 м),
5 картинок `heatmap_<i>.png` (тепловая карта совпадений + истинная и найденная точки),
`horizon_demo.gif` (5 случаев подряд, по 2 с). Отдельно — карта «где горизонт неуникален»:
для каждой точки расстояние до самой похожей точки дальше 100 м → `uniqueness.png`.

### 9.3 Что честно написать
Синтетика, не реальное фото. Реальное фото Perseverance — следующий шаг.
Похожий подход исследуют в NASA/JPL для роверов — мы применяем к астронавту.

## 10. P6 — схемы для слайдов `out/slides/`

SVG + PNG (1920×1080, тёмный фон, крупный текст), опционально `slides.pptx`:
1. `route.svg` — Карта высот NASA → слои (уклон, камни, доза) → цена клетки → поиск пути через
   цели → проверка кислорода и возврата → маршрут + карточка + зона возврата.
2. `horizon.svg` — Заранее: карта высот → силуэты из каждой точки. На Марсе: фото → линия горизонта →
   сравнение → «вы здесь ± N м». Бонус: силуэт → открытость неба → доза и укрытия.
   Вставить картинку `heatmap_*.png` и число ошибки из `stats.md`.
3. `ecosystem.svg` — Диспетчер ↔ Supabase (astronauts, missions, events) ↔ Корабль ↔ VR-шлем.
   Подпись: «положение астронавта — из локализации по горизонту, без GPS».

## 11. P7 — Supabase (только если нужно)

`export/supabase/schema.sql`:
- `astronauts(id text pk, x float, y float, h float, heading_deg float, o2_pct float, status text, updated_at timestamptz default now())`
- `missions(id text pk, data jsonb, version int, status text, updated_at timestamptz default now())`
- `events(id bigint generated always as identity pk, type text, payload jsonb, created_at timestamptz default now())`
  — `type`: `flare`, `storm`, `mission_update`, …
Для хакатона: RLS выключен или политика «читать/писать всем» (написать, что это только для демо).
`export/supabase/client.js`: опрос раз в 2 с; события — только новые (`id > lastSeenId`);
маршрут перезапрашивать только при смене `missions.version`.
